# Travel Map 后续验收与实施计划

**状态：待验收清单，2026-10-15 整理。** 旧 Phase 1–6 的实施过程与 Phase 7 的详细实验方案已移至[历史快照](../../../archive/footprint-ios-implementation-plan-pre-cleanup.md)。这些阶段曾标记“已完成”，本文件不把代码完成等同于真机或浏览器体验验收。产品与数据语义见[设计说明](design.md)。

## 已有基础

- iOS 已有前台位置采样、本地 pending 队列、幂等同步、MapKit 当前与历史行程地图、打卡详情及文本编辑。
- FastAPI 使用 `travel_footprints` 统一保存 `AUTO_GPS` 和 `MANUAL_CHECKIN`；`footprint_type` 区分来源，显式 `trackingSegmentUuid` 保存连续记录边界。兼容旧的 locations/checkins API。
- iOS 与 Web 已有多段轨迹、可信连接规则、双层描边和随缩放调整的自动点；同段打卡可作为轨迹顶点并保留独立标记。iOS 有受限平滑，Web 使用 Leaflet 折线简化。
- 这些描述是代码现状摘要；每次改动仍以当前代码及相关测试为准。

## 下一轮必须完成的验收

1. **共同数据样例：** 两端使用相同的步行、短暂停止与重启、弱信号、跨城市跳跃、无段 ID 历史、打卡位于可信段内的足迹数据。确认没有虚假长连线，打卡不会跨越段边界，地图不因劣质 GPS 缩远。
2. **视觉与交互：** iOS 真机及 Web 浏览器分别检查街道级与远景缩放下的点密度、双层线可读性、当前位置和打卡标记层级、急转与回头路线。开关自动点时，路线与打卡应保持不变。
3. **离线与多账号：** 断网采集后地图立即显示待传点；恢复网络时不闪失、不重复，重启后仍可补传。历史浏览不改变当前 Trip 的写入归属，账号切换不混入前一账号的点。
4. **性能基线：** 用约 100、1,000、5,000 个点的代表性 Trip 测首屏耗时、缩放帧率和内存，记录设备、系统、网络及测试数据范围。先取得数字，再决定是否缓存完成段、只增量更新活动段、分页或服务端聚合。

自动验证入口：Web `npm run test:footprints`；iOS `VagoIOSTests/FootprintGeometryTests.swift`；后端 `services/vago-ai/tests/test_footprints_service.py`。测试通过不能替代真机和浏览器视觉验收；执行前检查本机是否具备可用的 iOS Simulator runtime。

## 按证据触发的后续工作

- 若真实步行转角质量不足，再比较 iOS 当前约 20 米 `distanceFilter` 的采样质量与耗电；不要仅为更密的点降低间距。
- 若大行程出现实测瓶颈，再增加缓存、增量更新、范围读取或几何简化，且不得修改服务端原始足迹事实。
- Web 自动刷新、路线生长动画、深色底图和复杂地图承载层属于单独的体验决策，不作为当前验收前提。
- **World Fog 暂不自动推进。** 仅在用户明确要求时，根据[历史实验方案](../../../archive/footprint-ios-implementation-plan-pre-cleanup.md)重新核对现行代码与数据范围后立项。

交付时记录测试数据、设备与浏览器、操作步骤、期望与实际结果；明确写出已通过、未验证和发现的问题。
