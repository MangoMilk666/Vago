# 阶段 4：地点与路线来源

> 2026-10-26。D05 已明确分端验收：Web 本轮只验证中国大陆高德规划；iOS 目标是在中国大陆及选定境外地区使用原生 MapKit 完成地图和规划交互。高德 Web 服务 Key 已取得，Apple Maps Server API 凭据暂不可用。下列“已接入”仅指代码路径，真实服务和客户端能力仍按各自验收项确认。

## 已接入

- Vago 后端增加认证后的地点搜索、路线候选和地图预览接口：`POST /api/v1/agent/planning/places/search`、`POST /api/v1/agent/planning/routes/search`、`POST /api/v1/agent/planning/routes/preview`。大陆使用高德；境外 Apple Maps Server API 代码路径因无凭据暂不可验收。密钥仅由服务端环境变量读取。
- 延续 wkf 的“先找地点、再获取多个路线候选、选择一条路线”的流程。返回路线耗时、距离、来源、坐标系、查询时间和十分钟有效的 `routeChoiceId`。该 ID 由服务端签名并绑定当前用户、地点 ID、路线耗时与来源；候选版本创建或重新校验时核对签名。过期或被修改的引用不能通过来源核验。
- 高德地点/路线使用 GCJ-02，Apple 使用 WGS84。坐标系不匹配直接拒绝；规划结果不得作为实际足迹保存。Apple Maps Server API 未提供公交路线查询，境外公交返回 `MAP_MODE_UNSUPPORTED`，不会伪造路线或改用驾车时长。
- 候选 `content.days[].items[]` 如使用路线，应提供 `latitude`、`longitude`、`coordinateSystem`；对应 `legs[]` 应带 `mode` 和路线响应中的 `provider`、`routeChoiceId`、`routeDurationMinutes`、`queriedAt`。服务端同时核对路线端点坐标、用户归属、方式和耗时，不能把 A 点的路线引用挪给另一组地点。
- 无凭据、上游不可用、配额限制、无路线及不支持地区/交通方式均返回明确错误。候选仍受阶段 3 的时间、预算与硬约束检查约束。
- 三个外部查询入口按认证用户共用每分钟 12 次的 Redis 配额；配额服务不可用时直接告知，避免意外耗尽共享地图服务额度。

## 按 D05 调整后的验收

1. **Web 中国大陆：** 高德 Web 服务 Key 已在本机 FastAPI 配置。真实地点、步行/驾车/公交路线、短期路线引用及静态地图预览已通过服务层验收；还需验证登录后的浏览器交互、候选时间线、失败与限额提示及规划地图的坐标显示。
2. **iOS 中国大陆与境外：** 分别在选定城市验证原生 MapKit 地点、路线、交通方式及地图交互，不把“地图能显示”当作“规划查询可用”。iOS 侧的路线查询与候选计划接入尚待实现和验证；本项是目标能力，不是现状。
3. **共同边界：** 设备通过 MapKit 查询到的境外路线尚无服务端可信来源证明。正式候选遇到需要路线证据的硬约束时，按 D04 保持 `unverifiable`，不得因为 iOS 可显示路线就放行正式写入。高德 GCJ-02 与 Vago WGS84 坐标转换仍需在真实地图上核对。

Web 境外地点、路线及地图预览暂不纳入本轮验收；Apple Maps Server API 凭据和境外公交服务端来源不作为本轮前置条件。

## 本机真实服务验收记录

2026-10-26 运行 `cd services/vago-ai && PYTHONPATH=. .venv/bin/python scripts/verify_amap_live.py`。公开景点“上海外滩 → 东方明珠广播电视塔”的地点搜索成功；步行、驾车、公交分别返回 1、1、3 条路线。三种路线的用户、端点、坐标和耗时签名引用均通过校验。路线耗时随高德实时结果变化，不作为固定断言。

验收时发现公交 2.0 接口要求 `citycode`，原请求发送中文城市名，返回错误码 `20000`。现由地点结果传递 `cityCode`；结果缺少编码时，服务端通过高德行政区查询解析。上海返回的两个行政区候选均为 `021`，按一致编码继续查询。上游业务错误会附带数字错误码，便于定位配置或参数问题。对应规划候选 API 测试 9 项通过。

本次尚未完成登录后的 Web 浏览器交互验收、GCJ-02 与足迹 WGS84 的视觉核对及 iOS 境内外规划查询。因此阶段 4 仍处于实施中。

Web Agent 页面现已增加“地点与路线”面板：可按中国大陆城市搜索起终点、查询步行/驾车/公交路线并在当前面板选择候选。面板直接调用已有 FastAPI 接口，选择仅保存在当前页面状态中。候选计划持久化与 Agent Tooling 的连接仍未完成。

2026-10-26 后续补充：路线选择现在会请求登录用户专属的短期高德静态地图预览。FastAPI 从真实路段提取折线、在 Redis 暂存十分钟，用带签名的路线引用校验归属后代理地图图片；Web 不接收高德 Key。上海公开景点步行、驾车、公交三种路线均已取得真实 PNG，步行图人工查看能看到沿道路的紫色路线与起终点。Agent 顶栏保留“地点与路线”入口，旅行上下文、个人资料和预览上下文整合到左侧底部可展开设置。地图预览不写入 Plan 或足迹。

高德 Web 服务使用条款要求同时使用高德地图服务；本轮预览采用高德静态地图。现有独立足迹页仍用其他底图，跨模块/跨客户端的实际许可边界仍须核对。浏览器登录后的完整视觉和交互验收、候选计划保存、坐标核对以及 iOS 规划查询尚待完成。

## 配置与来源

环境变量见 `services/vago-ai/.env.example`。Apple 服务端私钥当前无需配置；未来启用时也只进入服务端，不放进客户端或仓库。当前 `routeChoiceId` 是短期签名引用，不是 Apple 或高德的永久路线 ID；正式 Plan 的长期来源保存与重新查询还需在阶段 7 的写入设计中复核。

接口与展示限制以高德路径规划 API、Apple Maps Server API 路线接口及 Apple 开发者协议为依据。
